# Day7: 強化学習 (RLHF / DPO / GRPO)

SFT だけでは学べない「人間が微妙に好む方」を学習させる強化学習を実装する。
DPO を中心に、RLHF の報酬モデルの数理、GRPO の仕組みまで検証する。

---

## 基礎編 `day7_dpo.py`

「丁寧な回答（chosen）」を「そっけない回答（rejected）」より好むよう、
選好データから DPO で学習させる。

```bash
python day7/day7_dpo.py
```

**実行結果（要約）:**
```text
=== ステップ1: DPO学習 (beta=0.5) ===
step    0 | DPO loss 0.693 | chosen-rejected logp差 +29.887
step  100 | DPO loss 0.000 | chosen-rejected logp差 +49.553
step  200 | DPO loss 0.000 | chosen-rejected logp差 +55.464
```

```text
=== 定量評価: log pi(chosen) - log pi(rejected) の変化 ===
DPO前（ref, ≈SFT直後）: +30.045
DPO後（theta）        : +56.547
→ 値がより大きくプラスになっていれば、chosen(丁寧な回答)がより選ばれやすくなった証拠
```

chosen と rejected の生成確率の差が広がり、丁寧な回答が選ばれやすくなった。
（学習しすぎで生成が崩れる DPO の弱点＝過剰最適化も同時に観測できる）

## 深掘り編 `day7_rl_deepdive.py`

RLHF の数理を3つの実験で検証する。

```bash
python day7/day7_rl_deepdive.py
```

### 実験1: Bradley-Terry モデルで報酬を復元
```text
特徴ごとの重み（真の値 vs 学習した報酬モデル）:
  丁寧さ: 真 +1.50  /  学習 +1.57
  正確さ: 真 +2.00  /  学習 +1.99
  簡潔さ: 真 +0.50  /  学習 +0.55
  無礼さ: 真 -3.00  /  学習 -2.96
→ 選好データ（どっちが好きか）だけから、報酬の構造を復元できた
  特に「無礼さ」がマイナスと学習できている＝人間の好みを捉えた
```

「どっちが好きか」という順位情報だけから、人間が重視する報酬の構造
（丁寧+、無礼−）を復元できる＝報酬モデルの本質。

### 実験3: GRPO のアドバンテージ計算（Critic 不要）
```text
質問: 日本の首都は?  （G=4個の回答をサンプリング）
回答                                            報酬       アドバンテージ
東京です。ご質問ありがとうございます。                       2.40         0.913  ↑良い
東京。                                       0.80        -0.149  ↓悪い
東京です。                                     1.90         0.581  ↑良い
分かりません。                                  -1.00        -1.344  ↓悪い

グループ平均報酬(baseline) = 1.025
→ 平均より上の回答は正のアドバンテージ（強化される）、
  下の回答は負（抑制される）。価値モデルなしでbaselineを実現。
  これがGRPOがPPOより軽量な理由。DeepSeek-R1等で採用された。
```

グループ平均を baseline にすることで価値モデル（Critic）を不要にする。
これが GRPO が PPO より軽量な理由で、DeepSeek-R1 で採用された。
