# Day8: データ整備と評価ベンチマーク

「AI に何を食べさせるか（データ整備）」と「AI の実力をどう測るか（評価）」を実装する。
MinHash による重複除去や、評価を歪める「データ汚染」の危険性を検証する。

---

## 基礎編 `day8_data_and_eval.py`

Perplexity・MinHash 重複除去・データ汚染の3つを実装する。

```bash
python day8/day8_data_and_eval.py
```

**実行結果（データ汚染の実演）:**
```text
[クリーン学習（ベンチマーク未混入）]
  「日本の首都は」の次の予測: 「面」
  正解「東」の予測確率: 0.0002
[汚染学習（ベンチマーク混入）]
  「日本の首都は」の次の予測: 「東」
  正解「東」の予測確率: 0.9957

→ 正解確率: クリーン 0.0002  vs  汚染 0.9957
  汚染した方が不当に高得点になる ＝ これがデータ汚染の怖さ。
```

テスト問題を学習データに混ぜるだけで正解率が **0.02% → 99%** に激変。
「賢くなった」のではなく答えを丸暗記しただけ＝データ汚染の恐ろしさ。

### 実験1: 「最小ハッシュの一致確率 = Jaccard 係数」をモンテカルロで証明
```text
正確なJaccard係数           : 0.4634
MinHash一致率（10000回試行）: 0.4677
誤差                        : 0.0043
→ 最小ハッシュの一致確率が、確かにJaccard係数に収束している
  【なぜ？】和集合A∪Bの中で最小になる要素はどれも等確率。
  その最小要素がA∩B（共通部分）に入る確率がまさに|A∩B|/|A∪B|＝Jaccard

ハッシュ関数の個数 k を変えたときの推定精度:
  k=   1 | 推定の平均 0.550 | ばらつき幅 1.000
  k=  10 | 推定の平均 0.460 | ばらつき幅 0.600
  k= 100 | 推定の平均 0.487 | ばらつき幅 0.200
  k=1000 | 推定の平均 0.467 | ばらつき幅 0.063
```

1万個のハッシュ関数で最小値一致率を実測すると Jaccard 係数に収束（誤差 0.004）。
MinHash が類似文書検出に使える数学的根拠を実験で確認した。

### 実験3: n-gram overlap によるデータ汚染の検出
```text
各学習文書との 文字5-gram 重複率:
  doc1: 重複率 0.00  (クリーン)
  doc2: 重複率 1.00  ⚠️ 汚染の疑い！
  doc3: 重複率 0.00  (クリーン)

→ しきい値0.3を超えたdoc2を汚染として検出。
```

ベンチマークと学習データ間の n-gram 重複を調べて汚染を検出する実務手法
（GPT-3・Llama の論文で使用）を実装した。
